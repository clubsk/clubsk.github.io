## 前言
攻击机IP：192.168.1.4

靶机IP：192.168.1.5

## 一、信息收集

`nmap -sV --min--rate 10000 -p- 192.168.1.5`

```
PORT    STATE SERVICE  VERSION
22/tcp  open  ssh      OpenSSH 8.6 (protocol 2.0)
80/tcp  open  http     Apache httpd 2.4.51 ((Fedora) OpenSSL/1.1.1l mod_wsgi/4.7.1 Python/3.9)
443/tcp open  ssl/http Apache httpd 2.4.51 ((Fedora) OpenSSL/1.1.1l mod_wsgi/4.7.1 Python/3.9)
```

经过初步扫描，我们可以发现开放了22、80、443端口，于是可以进行更加详细的扫描和漏洞发现，与此同时去查看了web服务,奇怪的是显示404。通过进一步扫描结果可以发现，它的ip的DNS解析指向两个域名

`DNS:earth.local, DNS:terratest.earth.local`

为了使得对域名的解析指向这个ip，我们需要在hosts文件中加上这样一条：192.168.1.5 earth.local terratest.earth.local

![](https://github.com/user-attachments/assets/d3a49ede-a415-4aa6-aafb-e4d30dbb9ed0)

![](https://github.com/user-attachments/assets/c1d89a71-82df-48cb-b474-7b7db95abf5f)

![](https://github.com/user-attachments/assets/b450d995-c56a-4b1c-ab1f-cd2b263195ba)

然后就可以正常访问，发现两个不同的域名他们的web页面都一样，有一个输入框，根据背景，应该是地面人员向太空传递信息用的，随便输点东西，会出来一些字符串；但是根据漏洞扫描结果，没有xss和csrf，用dnslogs测了一下，确实没有xss，并且根据对网页源码的观察可以发现对csrf进行了防护。漏洞扫描结果告诉我们，可以去访问它的/icons,但是吧，并没有有效信息。去看了下https页面，同样没啥东西。

![](https://github.com/user-attachments/assets/0c3c82de-1bf4-42d0-88b8-dcc8e75d79ae)

对两个域名的http和https页面进行目录爆破。通过爆破，我们不难发现，开放了一个admin登录页面，需要账号密码；还有一个值得关注的是：在对`https://terratest.earth.local`的目录扫描中，意外发现了一个robots.txt

## 三、漏洞利用
先去看一下这个testdata.txt，哇，发现一段废话。骗你的。根据xor的原理，如果把web页面的字符串当成密文，我们想要知道明文，就需要密钥，那么这一段废话是不是密钥呢🧐
